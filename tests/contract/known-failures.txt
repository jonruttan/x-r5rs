# --- The reader takes every token beginning with '.' as the pair-dot --------
#
# So `...` is unreadable: (a ... b) reads as an improper list terminated by the
# reader's internal pair-dot marker, which is a raw C satom and segfaults on
# access.  syntax-rules patterns are written in the ellipsis, so the whole
# group goes down together.
#
# Not a patch waiting to be applied.  x is not Scheme, and Scheme's lexical
# rules -- that `...` is a symbol, that `a.b` is a symbol -- are a lang's to
# impose above the engine rather than the engine's to adopt.  The route that
# does not ask the engine to become Scheme is a lang-owned tokenizer base via
# (Base make-tok), the primitive x-ash uses for shell syntax.  Not attempted.
